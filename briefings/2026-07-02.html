Fable 5 的安全架構留了一扇無人看守的後門

事實背景

Anthropic 於 2026-07-02 發表 Claude Sonnet 5，定位為「5 世代」首個中階模型（mid-tier model，介於旗艦 Opus 與輕量模型之間）。導入價 $2/$10 每百萬 input/output token，8/31 後調升至 $3/$15。Sonnet 5 在 agentic coding（能自主操作終端機、瀏覽器執行多步任務的 AI 代理）表現大幅超越前代 4.6，但資安 benchmark 反而比 4.6 更差，Anthropic 明確表示「未刻意訓練其資安能力」。同日，美國商務部解除對 Fable 5 與 Mythos 5 的出口管制（export controls，美國限制特定技術輸出給外國人的國安工具），兩個模型自 6/12 被政府強制下架後重新回歸，共停用 18 天。Fable 5 附帶安全分類器，可直接擋下特定資安與生物類請求，並提供自動 fallback 到 Opus 4.8 的選項，輸出資料保留 30 天。

So What?

研究指向一個確定的架構漏洞：Fable 5 分類器觸發後 fallback 到的 Opus 4.8，本身沒有同等分類器，等同官方設計了一條繞過路徑，攻擊者只需讓分類器觸發，即可在 Opus 4.8 上重試被擋的請求。真正受害的是靠「分類器存在」通過企業採購審查的安全長（CISO），他們核准的是前門，不知道後門是 Anthropic 自己開的。Sonnet 5 的資安 benchmark 退步更放大了這個風險，因為它的 agentic 能力恰恰讓多步驟攻擊鏈更難被人工察覺。

值得追問
  1. Fable 5 分類器擋下請求後，Anthropic 為什麼選擇 fallback 到一個沒有同等防護的 Opus 4.8，而不是直接回傳錯誤就結束？
  2. Sonnet 5 資安能力比前代更差，卻同時擁有更強的終端機與瀏覽器操作能力，這個組合在多步驟任務鏈遇到惡意環境時，具體的失敗模式是什麼？

Etched 的 $1B 合約是有條件的期權，不是剛性承諾

事實背景

推理晶片新創 Etched 於 2026-06-30 出關，公布已完成逾 $800M 募資（含最近一輪 $500M），去年 12 月投後估值（post-money valuation，含本輪募資後的公司估值）達 $5B，同時宣布已簽逾 $1B 客戶合約。晶片以台積電 N4P 製程生產，專攻純推理（inference-only）ASIC（特定用途積體電路，為單一任務客製），砍掉訓練用電路換取更低功耗或更高推理速度。投資人含 Peter Thiel、Jane Street、Hudson River Trading 等。公司計畫今夏開始向部分客戶出貨，目前仍在與客戶驗證機櫃級產品。

So What?

Jane Street、HRT 這類量化交易客戶簽合約的邏輯是先卡住稀缺算力配額，研究指出這些合約高機率是附性能驗收條款的 milestone-based 結構，本質上是有條件的期權，而非 take-or-pay 剛性承諾。更根本的架構風險是，Etched 在硬體層鎖死了標準 transformer 注意力機制，若 MoE（Mixture of Experts，稀疏路由架構）或線性注意力在推理端大規模落地，KV cache 記憶體通道設計會變成沉沒成本。在這個賭注上，Etched 比 Jalapeño 更脆弱，因為它連訓練彈性都沒有；真正的贏家反而是 Nvidia，其 CUDA 生態讓架構遷移的摩擦成本由軟體層吸收，不需重新流片。

值得追問
  1. 那 $1B 合約裡有多少是不可撤銷的 take-or-pay，多少是附帶性能驗收條款可以走人的，如果良率出問題，Etched 的帳上現金夠燒到第二批晶片嗎？
  2. 如果明天有人拿台積電 N4P 做另一顆純推理 ASIC，Etched 最難被複製的到底是晶片設計，還是靠 Jane Street 和 HRT 這批量化交易客戶綁出來的通路？

OpenAI 的軟體優化榨乾的是免費層，付費端還是要靠 Jalapeño

事實背景

據 The Information 首爆，OpenAI 工程師開發出一套推理優化方案，純靠提升既有 GPU 伺服器利用率，把部分模型推理成本砍掉逾一半，並使 ChatGPT visitor tier（免登入試用層）所需 GPU 從數萬顆降至數百顆。同日，OpenAI 與 Broadcom 公布首顆自研推理晶片 Jalapeño，為大模型推理從頭設計的 ASIC，9 個月開發完成、台積電代工，宣稱每 token 推理成本較現行 Nvidia GPU 低約 50%，鎖定 GPU 在 LLM 工作負載上的記憶體瓶頸。

So What?

visitor tier 從數萬顆 GPU 砍到數百顆，這個約 99% 的壓縮比幾乎確定不是純效率提升，而是 aggressive batching（積極批次處理）加上更高延遲容忍的組合。這套優化對延遲敏感的付費 API 用戶（即時語音助理、低延遲 coding agent）大概率不適用，這恰好解釋了為什麼 OpenAI 還需要 Jalapeño，因為軟體槓桿已在免費層榨乾，付費端降本還是要靠硬體。軟體優化真正受益的是 Broadcom，Jalapeño 的存在確認了 ASIC 路線的必要性，讓誤把「GPU 需求砍到數百顆」解讀為 OpenAI 整體算力需求下降的 Nvidia 空方判斷出錯。

值得追問
  1. 軟體優化把 visitor tier GPU 從數萬砍到數百，這說明之前的利用率爛到什麼程度，OpenAI 付費用戶的單位經濟真正轉正了沒有，還是只是免費層不再大量燒錢？
  2. Jalapeño 鎖定推理降本，但 Etched、Google TPU、AWS Trainium 全在搶同一塊，OpenAI 自研晶片的真正 GTM（上市策略）是只供自家還是敢賣給第三方？

AWS 的 $1B 是獲客成本，埃森哲才是真正的輸家

! 雲廠商正在把顧問業的落地利潤直接吞掉，這不是產品競爭，是商業模式替換。
事實背景

AWS 宣布投入 $1B 成立 Forward Deployed Engineering（FDE，前進部署工程，把工程師派駐客戶現場貼身共建的服務模式）組織，每組 5-6 名工程師駐點客戶約 45 天，將 agentic AI（能自主規劃多步任務的 AI 系統）的部署週期從數月壓縮到數天。全額由 AWS 自有資產負債表出資，不要求客戶預付。已進駐客戶包含 Allen Institute、Cox Automotive、NBA、NFL、Ricoh、Southwest Airlines。此舉呼應 OpenAI 與 Anthropic 的前進部署布局。

So What?

這 $1B 幾乎確定是獲客成本偽裝成業務投資，AWS 不要求客戶預付、回本邏輯是每個 FDE 客戶的 AWS 年度雲消費擴大倍數，而非 FDE 服務本身轉正。駐點工程師深入客戶私有資料與內部系統後，整套 agentic 工作流會以 AWS 原生服務（Bedrock、Lambda、S3）為骨架建置，換雲的遷移成本比換模型高一個數量級。輸家是埃森哲、Deloitte 等系統整合商，他們的 AI 落地中間利潤正被 AWS 直接吞掉，且 AWS 用的是補貼而非競爭，他們沒有對等的籌碼還擊。

值得追問
  1. AWS 內部有沒有追蹤駐點結束後客戶的自主留存率，還是這本質上就是設計來製造 lock-in 的？
  2. OpenAI 和 Anthropic 也在做前進部署，AWS 真正怕的是不是模型層被替換掉後 FDE 客戶直接帶著架構搬去 Azure，綁的到底是雲還是人？

Google 把影片成本壓到 $0.10 一秒，第一受益者是自家廣告部門

事實背景

Google 於 2026-06-30 推出 Nano Banana 2 Lite（約 4 秒生成一張 1K 解析度圖像、$0.034 一張）與 Gemini Omni Flash（$0.10/秒影片、與 Veo 3.1 Fast 同價，目前支援 10 秒片段）。兩者設計為串接工作流：用 Nano Banana 2 Lite 生圖、交給 Omni Flash 動畫化，形成「文字到圖到影片」的低成本生產線，鎖定產品與廣告創意。Omni Flash 在影片編輯榜目前僅次於 Seedance 2.0，已透過 Google AI Studio 和 Gemini API 對開發者開放。

So What?

Google 的廣告業務才是設計這條生產線的第一受益者。$0.034 圖加 $0.10/秒影片的組合完美對應 Google Ads 的素材大量生產需求，外部 API 定價本質上是用廣告業務的規模效益補貼開發者生態，順便把競爭對手的成本結構打爆。Runway 和 Pika 靠 per-asset（按件計費）定價建立的護城河直接消失，Sequoia 和 a16z 在這些公司的部位面臨重新標價壓力，除非這些公司能快速轉向細粒度編輯控制工具層而非生成層。

值得追問
  1. 靠 per-asset 收費的創意工具公司如果明天全部把底層換成這條生產線，Google 除了價格以外還有什麼護城河能防止自己變成純 commodity 供應商？
  2. 當單張圖降到三分錢、影片一毛錢一秒，Sequoia 和 a16z 在 Runway、Pika 的部位現在該怎麼重新標價？

Anthropic 的臨床前藥物研發，目前更像一個展示案例

事實背景

Anthropic 發表 Claude Science，一個整合論文審閱、資料庫、製圖與運算工作的科研 AI 工作台，連接 60+ 科學資料來源（涵蓋遺傳、蛋白質、化學、細胞資料），設計為可追溯研究每一步、保留可稽核軌跡。敏感資料可留在實驗室自有機器（on-prem，在地部署，資料不上雲），於 macOS 與 Linux 付費方案推出。同時，Anthropic 宣布啟動自家臨床前（preclinical，藥物進入人體試驗之前的實驗室與動物研究階段）藥物研發計畫，鎖定傳統大藥廠略過的罕見病。背景：Anthropic 過去一年大舉轉向科學領域，包含挖角 DeepMind 諾貝爾得主 John Jumper。

So What?

研究目前沒有發現獨立實體設立、濕實驗室招募或 IND 申報時間表的任何跡象，Anthropic 的臨床前研發宣告更接近高可信度展示案例，而非完整的藥物研發 pipeline。John Jumper 的真實角色是拉高科學可信度門檻，讓輝瑞、諾華這類大型藥廠相信 Anthropic 值得信任地處理機密研發資料，真正的策略意圖是打開製藥企業採購大門，不是真的要走到 IND 申報。on-prem 選項是 Claude Science 唯一對 BenchSci 和 Litmaps 這類已嵌入科學家工作流的競爭者有真實差異化的點，因為它正面解決了「機密資料不敢上雲」的製藥業痛點。

值得追問
  1. Anthropic 自己下場做罕見病臨床前研發，有沒有設立獨立實體、聘了多少濕實驗人員，還是六個月後這個計畫的主要產出是一篇部落格文章？
  2. 連接 60+ 資料來源聽起來很大，但科學家真正的痛點是資料清洗不是資料連接，跟 BenchSci 或 Litmaps 這些已經卡位的工具比，第 30 天的周活躍率是多少？
